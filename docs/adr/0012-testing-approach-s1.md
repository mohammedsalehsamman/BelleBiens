# ADR 0012: كيف نختبر تسجيل الدخول والواجهات (S1)

- **الحالة:** مقبول · 2026-11-11 · S1
- **قاعدة الاختبار في الباك إند:** اختبارات e2e تعمل على قاعدة PostgreSQL حقيقية منفصلة (`belle_test`)، تُنشأ وتُهجَّر تلقائياً. المزوّدون الخارجيون (SMS وواتساب والبريد وGoogle) لهم بدائل مزيفة في الاختبار تحتفظ بما "أُرسل"، والوقت مثبّت عبر `FixedClock`.
- **رمز تحقق ثابت للاختبار على الجهاز:** `OTP_FIXED_CODE` يجعل كل رمز يساوي قيمة معروفة، لتسجيل الدخول آلياً من المحاكي. التحقق من البيئة يرفضه في staging والإنتاج، ويجب أن يطابق طوله `OTP_LENGTH`.
- **الموبايل:** صور golden تُقبل بفرق حتى 2% من البكسلات، لأنها تُولَّد على Windows وتُفحص على Linux ويختلف تنعيم الحواف قليلاً.
- **الموبايل (تابع):**
  - اختبارات الواجهة تحمّل الخطوط الحقيقية (`test/flutter_test_config.dart`) حتى تقيس اختبارات العرض 360 وتكبير الخط النص الحقيقي.
  - صور golden بأسلوب Alchemist "CI goldens": النص يُرسم كمربعات، فتتطابق الصور بين Windows (حيث تُولَّد) وLinux (الـ CI).
  - عميل الـ API مولّد من `openapi.yaml` عبر swagger_parser 2 (retrofit وfreezed)، والـ CI يتحقق أنه مطابق للعقد.
- **النتائج:** لا يوجد اختبار يرسل رسالة حقيقية أو يلمس بيانات التطوير. اختبار `integration_test/sign_in_flow_test.dart` يحتاج الـ API محلياً مع `OTP_FIXED_CODE`.
